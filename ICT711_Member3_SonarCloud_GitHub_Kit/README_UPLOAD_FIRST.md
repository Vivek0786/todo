# ICT711 Member 3 — GitHub kit for SonarQube Cloud

**Status**: starter files only. The provided assessment ZIP includes Member 3 tests and
coverage configuration, **NOT** `todo/` source or measured `coverage.xml`.
Do not push this kit until `prepare-upload.ps1` has copied these from your machine.

## What to do on your Windows PC

1. Extract this zip into `C:\ict711\member3_github_kit` (or another short folder).
2. In PowerShell:

   ```powershell
   cd C:\ict711\member3_github_kit
   powershell -ExecutionPolicy Bypass -File .\prepare-upload.ps1
   ```

   It copies the real `todo/` source from `C:\ict711\django-todo\todo` and
   converts `C:\ict711\gtd\coverage.xml` to repo-relative `coverage.xml`.
   Neither Docker nor local SonarQube is needed.

3. Inspect the copied files and verify the source commit, license, and no secrets.
4. On SonarQube Cloud create/import a GitHub-connected project using **CI-based analysis**.
   Set `sonar.organization` and `sonar.projectKey` in `sonar-project.properties`
   to the two actual values, replacing the `REPLACE_...` strings.
5. Create a personal GitHub repository (private is recommended for student work).
6. Upload/commit **the contents** of this folder, retaining `.github/workflows/sonarqube-cloud.yml`.
7. Add a GitHub Actions secret named `SONAR_TOKEN` with your SonarQube Cloud analysis token
   at GitHub repository > Settings > Secrets and variables > Actions > New repository secret.
8. Push again (or use GitHub > Actions > ICT711 Member 3 > Run workflow), and check the
   scan result. The analysis runs on GitHub-hosted infrastructure, **not on your 5GB disk**.

## Files needed for the scan
- `todo/` — **the actual django-todo application source**, not in the original assessment ZIP.
- `coverage.xml` — generated by your real local test run, normalized by helper.
- `sonar-project.properties` — SonarQube Cloud configuration; replace TWO project keys.
- `.github/workflows/sonarqube-cloud.yml` — cloud runner workflow.
- `member3_tests/` — test source that explains how measured coverage was collected.
- `.gitignore` — excludes local database, secrets and environments.
- `LICENSE` (if available) and `UPSTREAM_SOURCE.txt` — preserve original attribution.

Other supplied `.ps1`, `.csv`, `.coveragerc` and `consolidate_results.py` files support
the Member 3 assessment records but are not needed for the cloud static scanner itself.

## Important limitations and evidence ethics
- **This cloud workflow scans actual source and imports saved coverage, but does not run Django
  tests on GitHub.** The original ZIP does not include the GTD host application/settings or its
  complete dependency environment, so remote test execution cannot be guaranteed from it.
- The coverage is a snapshot of a **partial failed test run**, not proof that all 16 team
  cases passed. The existing HTML title saying '16 cases' was only a title.
- Do not silently remove failing cases or alter coverage results. Rerun tests locally and
  regenerate coverage.xml if your source changes, then re-run prepare-upload.ps1 and commit.
- Keep personal credentials, student databases, screenshots, private reports and tokens off GitHub.
- If SonarQube says coverage is missing, inspect GitHub Actions's scanner log for import paths
  and verify source matches the coverage source exactly.
- A GitHub public repository may expose assessment content and third-party source code.
  Preserve upstream licensing and use a private repository if allowed by your project plan.
